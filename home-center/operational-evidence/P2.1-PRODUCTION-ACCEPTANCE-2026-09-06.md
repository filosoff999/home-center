## Accepted action boundary

The immutable registry contains exactly one executable action:

- ID: `service.state.read.v1`;
- permission: `service.read`;
- risk: `read-only`;
- targets: local node only;
- service allowlist: `home-center.service`, `home-center-backup.timer`;
- executor: absolute `/usr/bin/systemctl` argument vector;
- timeout: five seconds;
- idempotency: identical request replays stored result; conflicting material is rejected;
- recovery: `none-read-only`;
- evidence: request/result SHA-256 and HMAC-linked audit event.

No generic shell or bounded-change action is present.

## Rollback compatibility

P2 action metadata is stored in the sidecar `action_job_metadata` table. The P1 `jobs` table shape is unchanged, so the 0.1.0 binary does not expose P2 internal columns if an emergency binary rollback is required.

## Next boundary

P2.1 does not authorize service restart, configuration replacement or any other mutation. The next increment must define a dedicated bounded helper, complete policy scope, failure injection and rollback evidence before the first bounded-change action can be admitted.
