# Home Center 0.13.0 — Intent Planning

## Назначение

Home Center 0.13.0 поддерживает декларативное планирование инфраструктуры. Администратор или интерфейс Home Center описывает требуемый результат, а система преобразует его в закрытый детерминированный план действий.

Планирование не выполняет изменения инфраструктуры. Исполнение инфраструктурных операций через Intent API в версии 0.13.0 отключено.

## Базовый поток

1. Принимается закрытый `Intent Request`.
2. Проверяется аутентифицированная административная сессия.
3. Поле `actor` запроса сопоставляется с владельцем текущей сессии.
4. Policy Engine проверяет точное разрешение для выбранного intent-типа.
5. Проверяются параметры и обязательные ограничения безопасности.
6. Формируется детерминированная последовательность plan-only шагов.
7. Для потенциально опасных операций в плане фиксируется необходимость подтверждения.
8. При нарушении policy/safety-инвариантов возвращается состояние `blocked` без исполнительных шагов.

## Intent API

Аутентифицированное планирование доступно через:

`POST /api/v1/intents/plan`

Запрос должен соответствовать `home-center.intent-request.v1`, использовать только режим `plan` и проходить same-origin проверку для браузерного доступа. Ответ соответствует `home-center.intent-plan.v1` и имеет состояние `planned` или `blocked`.

API не принимает пароли, токены, секреты, приватные ключи или учётные данные в параметрах intent. Такие запросы отклоняются без помещения секретного значения в ответ или журнал планирования.

## Поддерживаемые intent-типы

### `node.drain`

План безопасного вывода узла в обслуживание. План блокируется при небезопасном quorum или риске потери обязательных сервисов.

### `storage.share.create`

План создания файлового хранилища с параметрами ёмкости, SMB/NFS, HA и опциональной политикой резервного копирования.

### `virtualization.workload.create`

Провайдер-независимый план создания VM или LXC. Home Center описывает требуемые CPU, RAM, диск и HA без привязки Core к конкретному гипервизору.

### `module.install`

План установки Market-модуля. Если разрешения модуля не подтверждены, intent блокируется до формирования исполнительного шага.

## Контракты

- `home-center.intent-request.v1`
- `home-center.intent-plan.v1`
- `home-center.intent-step.v1`
- OpenAPI `home-center-intents.v1`

Контракты закрыты для неизвестных полей верхнего уровня. Размеры и форматы идентификаторов и параметров ограничены.

## Инварианты безопасности

- только режим `plan`;
- production execution отключён;
- доступ только для распознанной локальной или AD административной сессии;
- заявленный `actor` обязан совпадать с аутентифицированной сессией;
- browser POST проходит same-origin проверку;
- Policy Engine работает по default-deny модели;
- порядок шагов строго последовательный и детерминированный;
- blocked-plan не содержит шагов выполнения;
- Intent Engine не предоставляет сетевой, файловый или process-execution surface;
- операции, которые требуют отдельного разрешения на исполнение, помечаются `execution_requires_approval`.
