# Home Center 0.11.0 Development Baseline

Status: **DEVELOPMENT STARTED**

## Lineage

- release branch: `release/0.11.0`;
- first implementation branch: `feature/0.11.0-market-contracts`;
- development predecessor: `release/0.10.0`;
- stable `main` remains independent.

Home Center 0.11.0 inherits accepted safety properties and the development contracts of 0.10.0. Changes from 0.10.0 are integrated only after compatibility and regression checks.

## Initial vertical slices

0.11.0 starts with a production-inert Market/Module supply-chain foundation:

- closed `ModuleManifest v2`;
- exact module and artifact identity;
- compatibility, dependency and conflict declarations;
- explicit capabilities, permissions and bounded action metadata;
- declared network, storage, health, backup and lifecycle requirements;
- deterministic fail-closed parsing and semantic validation;
- negative tests for ambiguity and undeclared authority.

The second production-inert increment adds:

- closed module provenance, DSSE envelope and publisher trust-policy contracts;
- ECDSA P-256/SHA-256 threshold verification through a fixed OpenSSL binary;
- a cycle-free canonical manifest binding that zeroes only the statement digest;
- exact archive digest/size and safe-member validation;
- atomic, idempotent content-addressed staging under a pre-provisioned trusted root.

## Safety boundary

This baseline creates no authority to:

- download, extract or execute a module;
- invoke a shell or caller-controlled command/path;
- extend the privileged helper;
- change services, firewall, storage, AD, DNS, DHCP or cluster membership;
- enable automatic failover;
- deploy 0.11.0 to `dc01` or `dc02`.

Development CI artifacts are not stable-promotion or deployment authority.

## Required gates

- Python 3.12 and 3.14 deterministic gates;
- JSON contract and semantic validation;
- unit, E2E and security-negative tests;
- reproducible build-twice artifact;
- compatibility review against 0.10.0;
- separate beta/release/production acceptance cycle before any deployment.

Production, if separately accepted later, continues to use `dc02 → canary/soak → dc01` with backup, rollback, peer mTLS, exact parity, Domain SID/DRS and protected-service sentinels.
