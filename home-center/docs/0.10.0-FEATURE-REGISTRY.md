# Home Center 0.10.0 Feature Registry

This registry is the scope-control ledger for the `release/0.10.0` branch.

| Capability | 0.10.0 state | Production authority | Evidence |
|---|---|---|---|
| Version identity | Implemented | None | source/package/Web `0.10.0`; CI branch/version gate |
| Core command envelope | Implemented | Plan only | closed JSON Schema, immutable bounded input, runtime validation |
| Core result/error envelopes | Implemented | None | closed JSON Schemas |
| Node Manager | Foundation | None | identity registry and drain preflight planner |
| Upgrade Engine | Foundation | None | exact identity and dc02-first rollout planner |
| Configuration Engine | Foundation | None | desired-change and lock planner |
| Service Manager | Foundation | None | deterministic dependency planner |
| Policy Engine | Foundation | None | exact rules, default deny, mutation disabled |
| Typed module payloads | Implemented | Plan only | five closed input schemas and five closed output schemas |
| Public HTTP Core API | Not admitted | None | compatibility matrix defines a later integration gate |
| Persistent jobs/reconcile | Not admitted | None | later safety-certified increment |
| Module execution/market | Not admitted | None | later release track |
| Automatic update/failover | Forbidden | None | requires independent acceptance |
| Production rollout | Frozen | None | requires full 0.10.0 release acceptance |

## Invariants

1. A `0.10.0` development build cannot activate production mutation.
2. All Core commands are closed and carry operation, idempotency, correlation,
   actor, reason, module, action, target, and `mode=plan` fields.
3. Unknown fields and all execution modes are rejected.
4. Policy decisions are default-deny and match exact module/action/mode rules.
5. Upgrade planning binds version, source revision, and artifact SHA-256.
6. Existing 0.9.x safety, E2E, and release gates remain mandatory.
7. Each action dispatches by an exact module/action pair and rejects unknown
   payload fields.
