# Home Center 0.10.0 Development Baseline

## Status

Core foundation implementation in progress on `release/0.10.0`.

This release is a development-only, production-inert successor to the
published `0.9.2` artifact. It does not authorize deployment to `dc01` or
`dc02`.

## Exact predecessor

- version: `0.9.2`;
- source revision: `689d90995a4f365e2f19640486b136b525f29c6d`;
- artifact SHA-256:
  `90d5cb0b657abfdd13f077b4a2347c5066fbaddcd4f4bfa6b25944e73a8abe87`.

## 0.10.0 scope

The first 0.10.0 increment establishes a versioned Core boundary:

- closed plan-only command, result, and error contracts;
- typed closed input/output payloads for the five admitted planning actions;
- `NodeManager` identity registry and drain preflight planning;
- `UpgradeEngine` exact release-identity and rollout planning;
- `ConfigurationEngine` desired-change and lock planning;
- `ServiceManager` deterministic dependency planning;
- `PolicyEngine` exact-rule authorization with default deny;
- a CI gate proving that the Core package contains no command execution
  primitive and that production mutation/activation flags remain false.

The Core foundation may describe a change. It cannot execute a change,
download an artifact, control a service, or mutate a production node.

## Explicit non-goals

- no public HTTP route is added in this increment;
- no background worker, reconciler, scheduler, or poller is enabled;
- no generic shell, argv, filesystem path, network destination, or package
  source is accepted from callers;
- no automatic update or automatic failover;
- no AD, DNS, DHCP, GPO, router, gateway, or certificate mutation;
- no deployment of 0.10.0 to `dc01` or `dc02` before full release
  acceptance.

## Qualification gates

- source/package/Web identity is exactly `0.10.0`;
- release-branch/version equality is enforced by CI;
- Python 3.12 and 3.14 validation;
- existing contract, unit, E2E, security, and build-twice gates;
- new Core unit and JSON Schema contract tests;
- explicit API v1 compatibility/versioning matrix;
- new side-effect/mutation security gate;
- exact `0.9.2 → 0.10.0` predecessor policy;
- reproducible artifact build and SHA-256 verification.

## Release flow

`development → CI → artifact validation → beta qualification → release acceptance → production rollout`

Publication, merge, or artifact creation does not imply production
acceptance. When separately approved, rollout remains
`dc02 → canary/soak → dc01 → cluster acceptance`.

## Parallel tracks

- `0.9.x` remains an independent maintenance/release line.
- Infrastructure and security maintenance remain independent from the Home
  Center application release track.
- Broader module execution, reconciliation, market, and automatic HA work
  require later, separately certified increments.
