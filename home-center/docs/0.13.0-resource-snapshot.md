# Home Center 0.13.0 — Resource Snapshot

## Назначение

Home Center предоставляет администратору единый read-only снимок вычислительных ресурсов управляемого кластера. Снимок используется как доверенный источник фактов для отображения состояния инфраструктуры и последующего preflight планирования Storage и Virtualization.

Данные формируются из последних сохранённых capability-наблюдений узлов. Клиентский интерфейс не может объявить дополнительные CPU, память или свободное место и тем самым изменить фактическую ёмкость, которую видит Home Center.

## API

`GET /api/v1/resources`

Доступ требует аутентифицированной административной сессии.

Ответ соответствует контракту `home-center.resource-snapshot.v1` и содержит:

- состояние готовности ресурсного снимка;
- количество ожидаемых, наблюдаемых и готовых узлов;
- суммарное количество CPU;
- суммарный объём памяти;
- суммарные значения root-storage total/used/free;
- минимальный набор ресурсных данных по каждому узлу;
- capability IDs, доступные на узле.

## Проверка достоверности

Перед включением узла в снимок Home Center сверяет сохранённую identity-запись узла с identity внутри его capability-документа. Несоответствие node ID, имени, роли или адреса блокирует формирование снимка.

Значения CPU, RAM и storage проходят типовые и диапазонные проверки. Неконсистентное хранилище, неизвестный статус узла, повторяющиеся identity или повреждённый capability-документ приводят к fail-closed результату.

## Граница публикуемых данных

Resource Snapshot не включает:

- IP-адреса узлов;
- machine identity hash;
- серийные номера оборудования;
- содержимое сервисного inventory;
- пароли, токены, ключи или другие секреты.

## Готовность к планированию

`planning_ready=true` выставляется только когда наблюдается ожидаемое deployment profile количество узлов и каждый из них имеет состояние `ready`.

При неполном или недоступном кластере снимок остаётся доступным для диагностики, но получает `state=degraded` и `planning_ready=false`.

## Безопасность

Resource Snapshot является исключительно read-only поверхностью. Поле `production_mutation_enabled` всегда равно `false`; API не предоставляет операций создания дисков, storage pools, VM/LXC или изменения конфигурации узлов.
