# Home Center 0.12.0 — Local Administrator password management

Status: REQUIRED
Target release: 0.12.0

## Requirement

Home Center 0.12.0 must provide a supported password-change and recovery/reset workflow for the local administrator account `admin`.

### Password-change workflow

- Available through the standard Home Center administration interface and corresponding authenticated API.
- Must not require manual deletion or ad-hoc replacement of `/etc/home-center/secrets/local-admin.json`.
- Normal password change must require verification of the current administrator password.
- A protected recovery/reset workflow must exist for the case where the current password is unavailable.
- Password material must never be written to logs, audit payloads, command-line arguments, environment variables, GitHub issues/artifacts, or other persistent operational evidence.
- Credential storage continues to use a fresh random salt and a one-way scrypt verifier; plaintext or reversible password storage is forbidden.
- Rotation must preserve rollback/recovery semantics and must be safe for single-node and multi-node deployments.
- For a two-node deployment such as dc01/dc02, the workflow must explicitly reconcile the intended administrator credential state on both nodes without copying verifier bytes between nodes; each node retains an independently salted verifier.

## Password complexity policy

A new local administrator password is accepted only when all of the following are true:

- minimum length: 8 characters;
- contains at least one letter;
- contains at least one decimal digit;
- passwords consisting only of letters or only of digits are rejected.

The same policy applies to both normal password change and recovery/reset.

## Audit and security

Audit records may contain only non-secret metadata such as operation type, actor/session identity, target node(s), result, timestamp, and policy result. Passwords, salts, verifiers, legacy credential material, and derived secret values must never be emitted.

## Acceptance criteria

1. A valid password meeting the policy can be set and subsequently used for local administrator login.
2. Passwords shorter than 8 characters are rejected.
3. Passwords without letters are rejected.
4. Passwords without digits are rejected.
5. Failed rotation leaves the previous credential usable and does not create a partial credential state.
6. Successful rotation uses a fresh salt and produces node-local verifier state without exposing secret material.
7. Multi-node acceptance proves consistent login behavior on every intended node while verifier bytes/salts remain independently generated.
8. Recovery/reset is explicitly gated, auditable, and does not require publishing a secret through the remote execution channel.
9. Regression tests cover API, browser UI, invalid policy cases, rollback/failure paths, and two-node behavior.
