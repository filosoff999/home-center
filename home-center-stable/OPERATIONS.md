# Эксплуатация и восстановление

Текущий Public Stable **0.63.0** квалифицирован в профиле `single-node-core`. Эксплуатационные инструкции для peer/replication, rolling update, automatic failover и других multi-node/HA сценариев применяются только к отдельно опубликованной release identity, где соответствующий профиль явно заявлен и квалифицирован.

Контролируйте аутентифицированные health-представления, типизированную инфраструктурную инвентаризацию, TLS, backup и Audit. Несогласованность identity инвентаризации трактуйте как unavailable/unknown: отклонённые или неподтверждённые факты не должны отображаться как достоверное состояние.

Храните не менее двух независимо проверяемых backup для критичных данных и регулярно выполняйте restore drill. Наличие backup без проверенного восстановления не считается достаточным доказательством защиты данных.

Provisioning и recovery локального администратора выполняются только через локальный root-controlled контур. Пароль пользователя `admin`, установленный после обязательной смены при первом входе, должен сохраняться при обновлении.

Для `single-node-core` блокирующими состояниями являются неполная release identity, ошибка Audit integrity, повреждённая/некорректная конфигурация или неуспешная post-condition verification. Не продолжайте activation/update, пока причина не устранена либо система не восстановлена по квалифицированному rollback/recovery path.

Если конкретная отдельная release identity квалифицирует multi-node/HA, Degraded peer health также является блокирующим состоянием. Rolling update разрешён только по процедуре этого профиля: не переходите к следующему узлу, пока предыдущий узел не прошёл требуемые health/peer/replication/services verification либо не был безопасно восстановлен.
